Конечный автомат — абстракция, которая выполняет заданный алгоритм. В основе лежит набор состояний. Состояние конечного автомата определяет этот автомат.

Конечный автомат задают через три множества и две функции.
Первая функция — определение нового состояния. Вторая функция — определение финального состояния.

Архитектурно мы можем это изобразить следующим образом:
- Регистр состояни
- CL (Combination Logic). Она определяет новое состояние

Чтобы перейти к процессорному ядру нужно решить следующую задачу: в случае определения конечного автомата мы имеем строго определенные CL, а процессор мы можем программировани. Идея следующая – вместо CL организуем таблицу

таблица переходов — память команд, в которые мы загружаем программу
есть у нас еще счетчик команд, program counter (PC).

любая программа должна отвечать на три вопроса:
- что делать с данными?
- откуда брать данные?
- куда складывать результат?

программа может быть разбита по полям, каждое из которых будет отвечать на поставленные вопросы. любая команда представляется в бинарном виде. 

| Код операции | Адрес Операнда 1 | Адрес Операнда 2 | Адрес результата |
| ------------ | ---------------- | ---------------- | ---------------- |

Есть память данных, а также набор регистров процессоров. На системном уровне это одно и то же. Если же говорить о физике процесса, то к регистрам быстрее обратиться, чем к памяти данных.

``` Verilog
`timescale 1ns / 1ps
module Top(
	input wire a, b, clk
	output reg c
	);
	
// assign c = a & b

always @(posedge clk)
	c <= a + b;
	
reg a1, b1, c1;

always @(posedge clk)
begin
	a1 <= a;
	b1 <= a1 + 1;
	c1 <= a1 + b1;
end

reg a2, b2, c;
always @(posedge clk)
begin
	a2 = b;
	b2 + a2 + 1;
	c = a2 + b2;
end
	
endmodule
```
