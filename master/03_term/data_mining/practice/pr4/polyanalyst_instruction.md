### 1.2. Скрипт подготовки

Сохраните как `create_csv_file.py` и запустите. Для пробного прогона поставьте `N = 500`.

```python
import pandas as pd

df = pd.read_json("hf://datasets/blinoff/kinopoisk/kinopoisk.jsonl", lines=True)
df = df.dropna(subset=["content", "grade3"])
df = df.drop_duplicates(subset="review_id").drop_duplicates(subset="content")

# чистка: убираем «утёкшие» оценки и лишние пробелы, обрезаем длину
leak = r"\b\d{1,2}\s*(?:/|из)\s*10\b|\b\d{1,2}\s*баллов?\b|\b\d\s*\*"
df["text"] = (df["content"]
              .str.replace(leak, " ", regex=True)
              .str.replace(r"\s+", " ", regex=True)
              .str.strip()
              .str.slice(0, 1000))
df = df[df["text"].str.len() >= 100]

print(df["grade3"].value_counts())  # проверка: какие значения и сколько

# сбалансированная случайная выборка
N = 1500
N = min(N, df["grade3"].value_counts().min())
sample = (df.groupby("grade3").sample(n=N, random_state=42)
            .sample(frac=1, random_state=42)
            .reset_index(drop=True))

sample["label"] = sample["grade3"].map(
    {"Good": "positive", "Neutral": "neutral", "Bad": "negative"})
print(sample["label"].isna().sum(), "строк без метки (должно быть 0)")

# стратифицированное разбиение 70/30
test_idx = sample.groupby("label").sample(frac=0.3, random_state=42).index
sample["set"] = "train"
sample.loc[test_idx, "set"] = "test"

# сохранение
cols = ["review_id", "text", "label", "set"]
sample[cols].to_csv("kinopoisk_3class.csv", index=False, encoding="utf-8")
sample[sample["set"] == "train"][cols].to_csv("kinopoisk_train.csv", index=False, encoding="utf-8")
sample[sample["set"] == "test"][cols].to_csv("kinopoisk_test.csv", index=False, encoding="utf-8")

print(sample.groupby(["set", "label"]).size())
print("Сохранено: kinopoisk_3class.csv, kinopoisk_train.csv, kinopoisk_test.csv")
```

### 1.3. Что должно получиться

В папке появятся три файла:
- `kinopoisk_3class.csv` (все данные, колонка `set` = train/test);
- `kinopoisk_train.csv` (обучающая выборка, 70%);
- `kinopoisk_test.csv` (тестовая выборка, 30%).

Колонки: `review_id`, `text`, `label` (positive / neutral / negative), `set`.

При `N = 1500` будет 4500 строк: 3150 train и 1350 test (по 1050 и 450 на класс).

**Скриншоты:** С1 (первые строки CSV), С2 (вывод `print(sample.groupby(["set","label"]).size())`).

## 2. Общие правила работы в PolyAnalyst

1. Создайте **новый проект** и сразу назовите его осмысленно (например, `Практика4_Тональность`).
2. Сценарий анализа строится как **граф узлов**: каждый узел берёт таблицу от предыдущего, обрабатывает её и отдаёт дальше. Новый узел добавляется через меню или перетаскиванием из списка узлов, затем соединяется стрелкой с предыдущим.
3. Узел нужно **выполнить** (кнопка Execute / Run **[проверить]**) и дождаться зелёного статуса. Результат смотрите двойным кликом по узлу.
4. Давайте узлам **понятные имена** (например, «Импорт train», «Фильтр коротких»). Это пригодится для скриншотов.
5. **Сохраняйте проект** после каждого этапа. Веб-версии бывают с ограничениями по объёму и времени сессии.
6. Если песочница тормозит, сначала проверьте всё на маленькой выборке (`N = 500`).
7. Делайте скриншоты по ходу работы, а не потом: настройки узла + результат.

## 4. Этап 2. Очистка текста

Задача этапа: убрать мусор, который мешает классификации.

1. **Фильтр по длине.** Добавьте узел фильтрации строк **[проверить]**: оставить строки, где длина `text` ≥ 100 символов. (Скрипт уже сделал это, но можно показать в PolyAnalyst как контроль.)
2. **Пустые и дубли.** Проверьте, что нет пустых `text` и повторов (узел удаления дубликатов или фильтр **[проверить]**).
3. **Стоп-слова, лемматизация, регистр.** В PolyAnalyst это обычно делается **внутри текстовых узлов** (морфологический анализ + список стоп-слов). Поэтому отдельного узла «очистки» может не быть. В настройках текстового узла проверьте:
   - **язык: русский**;
   - **лемматизация** включена (слова приводятся к начальной форме: «понравился» → «понравиться»);
   - **стоп-слова** включены (предлоги, союзы, «и», «в», «на» и т.п.).
4. **Не удаляйте отрицания** («не», «ни», «нет», «без»), если они в списке стоп-слов! Для тональности это критично: «не понравился» и «понравился» противоположны. Если такая настройка есть, исключите их из стоп-слов.
5. Покажите пример **«до / после»**: один отзыв как в исходнике и его набор лемм после обработки (по результату текстового узла).

**Скриншоты:** С6 (настройки очистки / фильтра), С7 (пример «до и после»).

**Что написать в отчёте:** какие операции выполнены в Python (чистка утечек оценок, обрезка до 1000 символов, дубли) и какие в PolyAnalyst (лемматизация, стоп-слова), и **почему** (шум, одна лексема в разных формах, отрицания).

### 7.3. Метрики

Если узел сам выдаёт метрики, возьмите их. Если нет, считайте вручную по матрице.

**Accuracy** = (сумма диагонали) / (все документы в test).

Для каждого класса *c*:
- **Precision(c)** = TP(c) / (TP(c) + FP(c)). Из всех документов, которые модель назвала *c*, какая доля действительно *c*. FP(c) = сумма **столбца** *c* без диагонального элемента.
- **Recall(c)** = TP(c) / (TP(c) + FN(c)). Из всех реальных документов класса *c* какую долю модель нашла. FN(c) = сумма **строки** *c* без диагонального элемента.

Общие показатели по трём классам: **macro-precision** и **macro-recall** = простое среднее по трём классам.

## 8. Этап 6. Наиболее значимые слова

Нужно найти слова, которые сильнее всего влияют на решение классификатора. Сделайте **два способа** из трёх:

1. **Из самого узла классификации**: список ключевых терминов по каждой категории (если показывает). Выпишите топ-10…20 на класс.
2. **Из дерева решений** (путь Б): слова в верхних узлах дерева, самые важные правила.
3. **Резервный вариант вне PolyAnalyst** (по таблице train): для каждого слова доля в позитивных / негативных документах, берёте самые «перекошенные». Либо коэффициенты логистической регрессии:

```python
import numpy as np
import pandas as pd
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.linear_model import LogisticRegression

train = pd.read_csv("kinopoisk_train.csv")
vec = CountVectorizer(min_df=5, max_features=20000)
X = vec.fit_transform(train.text)
clf = LogisticRegression(max_iter=1000).fit(X, train.label)
words = np.array(vec.get_feature_names_out())
for i, c in enumerate(clf.classes_):
    top = np.argsort(clf.coef_[i])[-20:][::-1]
    print(c, list(words[top]))
```
(Этот вариант не лемматизирует слова. Если используете его, **честно напишите в отчёте**, что это вспомогательная проверка, а не результат PolyAnalyst.)

**Скриншот:** С16 (значимые слова по классам).

**Что написать:** по 10 слов на класс, краткая интерпретация (например, для negative: «скучный», «разочарование», «время»; для positive: «шедевр», «великолепный»). Для neutral значимых слов обычно мало, объясните почему.

## 9. Дополнительное задание: rule-based против машинного обучения

### 9.1. Rule-based подход

Два варианта (лучше оба, но достаточно одного):

**Вариант 1. Встроенный узел анализа тональности PolyAnalyst** **[проверить: Sentiment Analysis]**:
1. Подключите узел к таблице **test**.
2. Язык: русский. Режим: тональность **документа целиком** (не по отдельным понятиям).
3. Результат: колонка с тональностью (позитив / негатив / нейтраль или числовой балл). Если балл числовой, задайте пороги вручную (например, < −0.2 → negative, > 0.2 → positive, иначе neutral) и **обоснуйте пороги**.
4. Это подход «из коробки»: правила и словарь уже внутри системы, обучение не нужно.

**Вариант 2. Свой словарь правил.** Составьте список позитивных и негативных слов (по значимым словам из этапа 6 + общеизвестные) и считайте тональность по разнице количества позитивных и негативных слов, с учётом отрицания («не» перед словом меняет знак). Если разность около нуля, то neutral. Реализуется выражением в узле вычислений PolyAnalyst **[проверить]** или в Python.

### 9.4. Что обсудить

## 11. Если что-то не получается

- **Нет нужного узла.** Откройте список всех узлов и найдите по ключевым словам: «классификация», «тональность», «ключевые слова», «текст», «обучение». Если в песочнице нет узла обучения текстового классификатора, делайте путь Б (ML-узлы на признаках) или заявите это в отчёте и подтвердите свою часть работы Python-расчётом (с пометкой).
- **Песочница тормозит или падает на большом объёме.** Уменьшите `N` до 500–1000, пересоздайте файлы. Оставьте текст короче (например, 500 символов).
- **Кракозябры.** Другая кодировка (`utf-8-sig`), либо загрузите XLSX.
- **Все предсказания одного класса.** Классы несбалансированы или модель не обучилась. Проверьте, что в train по равному числу отзывов на класс и что целевая колонка выбрана верно.
