# Практическая работа № 4. Архитектура, управляемая моделью (Model-driven architecture, MDA)

## Цель работы
Освоить  раздельное  моделирование  CIM  →  PIM  →  PSM,  задать  правила трансформации  PIM→PSM  и  сгенерировать  хотя  бы  один  артефакт (код/контракт/схему) из модели.

## Задание
1. Определите систему
- Продолжайте  тему  из  ПР-1/2/3  (мониторинг  1С,  учёт  оборудования, делегирование задач и т. п.).
- Выберите  1–2  ключевых  сценария  (вертикальный  срез),  с  которыми будете работать.
2. Постройте CIM (контекст и смысл, без техники)
- Акторы, цели, ограничения и риски.
- Диаграмма контекста (допустимо C4-L0) + 1–2 Use Case.
- Итог: краткое описание сценариев (Job Story или Given–When–Then).
3. Постройте PIM (платформенно-независимая модель)
- Диаграмма  классов/компонентов,  1  диаграмма  последовательностей  по выбранному сценарию.
- Инварианты домена (текстом или OCL).
- Запрещено  упоминать  технологические  детали (SQL-типы,  REST-маршруты, брокеры и т. п.).
4. Выберите целевую платформу (PSM)
- Примеры: Java+Spring+PostgreSQL / .NET+WebAPI+MS SQL / Python+FastAPI+PostgreSQL / 1С+HTTP-сервисы / Go+gRPC+ClickHouse.
- Зафиксируйте ключевые качества (например: p95 ≤ 300 мс; install ≤ 10 мин; доступность 99.9%).
5. Опишите правила трансформации PIM→PSM
- Вариант  A:  таблица  соответствий  (PIM-сущность/связь/сервис  →  PSM-таблица/контракт/событие + правила).
- Вариант B: фрагмент ATL/QVT (для 1 сценария).
- Укажите политики: транзакции, идемпотентность, ошибки.
6. Постройте PSM (платформенно-зависимая модель)
- Схема БД (таблицы, типы, индексы, ограничения).
- Контракты API (OpenAPI/AsyncAPI) для сценария.
- Диаграмма развёртывания (узлы, зависимости, границы отказов).
7. Выполните генерацию (минимум 1 артефакт)
- Примеры: каркасы DTO/репозиториев/контроллеров; миграции БД; клиент по OpenAPI.
- Сгенерированное положите в /gen, приложите команду запуска.
8. Проведите проверку соответствия
- Мини-тест/скрипт:  вызов  сгенерированного  API,  применение  миграции, проверка уникального ограничения и т. п.
- Покажите, что артефакт работоспособен и соответствует сценарию/ограничениям.
9. Зафиксируйте архитектурные решения (ADR)
- 1–2 ADR: контекст → варианты → выбранное → последствия (например, «идемпотентность через ключ + уникальный индекс»).
10. Оформите результаты
- Отчёт:  CIM,  PIM,  правила  трансформации,  PSM,  что  сгенерировано,  как проверено, ADR, выводы.
- Трассируемость: таблица «Требование → элемент PIM → элемент PSM → артефакт/тест».
- README:  как воспроизвести генерацию/проверку (инструменты, команды).

## Дополнительное задание (по выбору)

- Две PSM из одного PIM (сравнение различий и последствий).
- ATL/QVT-трансформация фрагмента с автоматической генерацией.
- OCL-инварианты и их проверка в тестах.
- XMI-экспорт и «диаграммы как код» из одной модели.
